https://github.com/ardacankyaa/rimvo

Use Node.js 24 (or the supported version in `.nvmrc`) and npm. From a checkout of RIMVO:

```sh
npm ci
npm run build -- --base=/rimvo/
```

`dist/` is an ordinary static site; no signing key, server account or activation is required to build or run a modified copy. Serve it with a static server. For the public-path build above, mount `dist/` at `/rimvo/`; `npm run build` instead produces a portable relative-path build for local preview with `npm run preview`.

### Modify, rebuild and recombine the encoder with RIMVO

Extract the MP3 source archive into a separate directory. In that directory, edit the JavaScript sources as desired, then run:

```sh
npm install --ignore-scripts --no-audit --no-fund
npm run build
```

The provided upstream build produces `dist/lamejs.js` (ES module) and `dist/lamejs.iife.js`. These commands were exercised against the supplied unmodified sources, and the rebuilt module encoded stereo PCM successfully. Dependency resolution can change generated bytes; byte-identical reproduction is not required to make and use a modified encoder. The upstream pnpm lockfile is included for consumers who want its original dependency resolutions.

From the RIMVO checkout, install the rebuilt directory as a local replacement. Substitute an absolute path to the extracted encoder folder, quoted if it contains spaces:

```sh
npm ci
npm install --no-save --package-lock=false "/absolute/path/to/lamejs-source"
npm run build -- --base=/rimvo/
npx vitest run tests/recording/mp3.test.ts
```

On Windows, a path such as `C:/work/lamejs-source` is valid. This replacement leaves the tracked dependency manifest/lockfile unchanged. Vite resolves the replacement's public `Mp3Encoder` export and includes it when rebuilding the MP3 worker. This local replacement was tested with a successful RIMVO production build and all four MP3 export tests (including 44.1, 48 and 96 kHz). `npm ci` restores the original published dependencies afterward.

The project MIT terms do not prohibit modifying/replacing LGPL portions or reverse engineering to debug those modifications. Keep applicable notices and source availability with redistributed builds. This source/rebuild route accompanies the bundled worker; separating code into a worker alone is not asserted to satisfy LGPL obligations.

## Integrity and offline distribution

`source/manifest.json` lists the source-archive and license-text SHA-256 hashes, original package coordinates and provenance URLs. These are downloadable beside the JavaScript on the same site; no account or other service is required.

For an offline or mirrored distribution, retain this page, `THIRD_PARTY_LICENSES.txt`, `THIRD-PARTY-NOTICES.txt`, the complete `licenses/` directory, and the `source/` archives and manifest alongside the generated application. They are copied by Vite from `public/` to `dist/`. The original upstream licenses and notices remain attached to their implementations.

Run `npm run check:licenses` in the current repository, and `npm run check:licenses -- --dist` after building, to verify these materials and the runtime-source reference. When runtime sources change, update the immutable application-source revision and digest together before releasing.
